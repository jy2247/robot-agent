# 实现顺序与优化方向

1. **FC 契约**：确认 task/episode/frame 标识、五阶段判据、错误类型和重规划反馈。
   当前 task 来自配置，阶段名为示例；先对齐真实任务再接相机。
2. **真实 VLM baseline**：单帧图像 → JSON → FC；确认模型 ID、模板和多图支持。
3. **时序评测**：收集成功、失败、遮挡、阶段过渡视频；按 episode 划分数据，标注阶段/成功/错误。
4. **在线观察**：接 ROS2 或相机桥接器，定义帧有效期、最新帧优先队列、超时和取消策略。
   目前 HTTP 入口串行；生产实时任务必须避免积压。
5. **性能优化**：测量后比较图像分辨率、抽帧、历史长度、短 JSON 输出、服务端 prefix cache、量化和模型规模。
6. **闭环实验**：由 FC 将 critic 建议映射为继续、暂停、复核或重规划，记录恢复成功率。

## Benchmark 计划（尚未实现完整 evaluator）

| 方向 | 指标 |
|---|---|
| 阶段识别 | accuracy、macro-F1、阶段混淆矩阵 |
| 完成检测 | precision/recall、提前误报率、检测延迟 |
| 失败检测 | precision/recall、错误类别与误报率 |
| 工程性能 | 全链路及各段 P50/P95 延迟、deadline miss rate、显存 |
| 闭环收益 | 任务成功率、恢复成功率、无效重规划次数 |

按同一测试集比较：单帧 vs 历史帧；历史 1/2/4/8；不同分辨率；缓存启用/禁用。
