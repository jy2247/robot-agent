# V4：第三步简化为对准

用户最新要求：移液器尖端在所持试管口上方并对准，即第三步成功；不再要求插入、按压或移液。
三份 pipette 配置、系统 prompt、README 和 AGENTS.md 最新说明已同步。原 V3 报告保留为历史记录。

新增提示要求优先检查当前物体状态，对已满足物理成功条件而未记入完成记录的阶段及时输出完成。
上一轮完整判断不再作为模型输入，避免复制过时的“仍然拿着试管”等描述。没有通过视频标签、
阶段索引或事后规则强行补齐阶段。取物、回架仍需各自的可见成功证据。

## 实际验证

27 项回归测试通过。使用本机 Qwen/Qwen3.8-27B，对原十样本中的 success_02、failure_05 回放。
最终一轮：1 Hz 源抽帧、448px、1 个历史观测和初始参考图，两个 episode 并行、内部顺序推理。

| 样本 | 最终结果 | 仍需注意 |
|---|---|---|
| success_02 | 五阶段全部确认、顺序为 1→2→3→4→5；整体 SUCCESS；无物理失败误报 | 回管完成确认较晚，在第五段才得到确认；阶段匹配率 78.43% |
| failure_05 | 整体 FAILED / INCOMPLETE_AT_END | 本轮没有识别出 object_dropped，不能将整体失败算作掉落检测成功 |

最终 86 次推理，平均 4937.3 ms，约 0.203 次/秒。这是离线处理，不代表实时 1 Hz 推理。
只有两个样本，不能据此推断完整十样本或其他场景的正确率。

## failure_05 是漏识别，不是来不及读末帧

旧 V3 的末帧 1018（源时间 33.933 秒）已实际推理，耗时约 5449 ms，但仍输出 in_progress。
代码对每次推理等待完成，没有因视频播放结束而取消末帧。当前图像里手已打开，管子在桌面上，
模型却重复了历史“管子仍被拿着”的描述。速度不足是真实问题，但不是这次漏检的解释。

本轮较早的 V4 版本（0.5 Hz）在末帧输出了 object_dropped，但也在第 540 帧误报；检查该帧
ego 图像可见管子仍在手附近，不能把这次提前报告视为提前正确检测。细化物体身份判据后的
最终版本没有该误报，但末帧又漏检。另一次仅当前末帧、672px 的独立检查仍未找到桌面的管子。
因此掉落检测还不可靠，不能宣称修好了。该样本的小物体识别需要进一步验证。

## 视频显示修正

已确认完成的当前阶段保持绿色，不再被黄色“当前阶段”覆盖；已记录失败保持红色。
终止时显示整体 FINAL SUCCESS/FAILED，末尾增加明确标注的两秒停留，便于看清最后判断。
两秒只用于展示，不增加源观测或改变预测。新版本重渲染输出为 result_review.mp4，保留原视频。

最终目录：`outputs/critic-v4-aim-checkpoints-review/`，每个样本有 predictions.json、summary.json、
result.mp4、result_review.mp4 和 final_preview.jpg；根目录有 batch_summary.json 和 prompt/TOML 快照。
较早版本保留在 `outputs/critic-v4-aim-only-review/`，不与最终结果混用。
